## 引言：一场被商业利益裹挟的技术争论

最近 Latent.Space 的一篇文章在 AI 工程圈引发了不小的讨论。文章的核心问题是：**Harness Engineering 到底有没有真实价值？**

什么是 Harness？按照文章的定义，它是工程学科中通用的一个层级，作用是**连接、保护、编排组件**，自身并不执行具体工作。在 AI 工程里，它大致对应我们常说的 Agent Framework、编排层、或者更抽象的"AI 应用架构"。

这场争论的两端，分别站着两个阵营：

- **Big Model 阵营**：模型本身是核心，Harness 只需要极简封装，复杂的架构最终都会被更强大的模型取代
- **Big Harness 阵营**：Harness 是核心产品，经过精心优化的编排层能显著提升所有模型的效果

有趣的是，这两个阵营的分歧很大程度上源于**商业立场**——一个卖模型，一个卖 Harness 产品。当然，行业里也有更务实的观点认为两者都有价值。

那么，真相到底是什么？

## 一、Big Model 阵营：模型至上论的自信与傲慢

### 1. Claude Code 团队的极简主义宣言

Claude Code 团队的态度非常明确：他们的 Harness 只是对模型的**极简封装**，核心优势**全部在模型本身**。他们甚至表示会持续精简、重构代码，去掉一切不必要的复杂性。

这个观点背后有一个强有力的逻辑：如果模型足够强大，它应该能够自己完成大部分工作，而不需要复杂的脚手架。

### 2. Noam Brown 的"统一模型"预言

OpenAI 的研究科学家 Noam Brown 提出了一个更激进的观点：随着推理模型（Reasoning Models）的出现，此前为了实现推理能力而搭建的**复杂脚手架、模型路由器等都会被更强大的模型替代**，未来将走向**单一统一模型**。

这个观点如果成真，意味着现在投入大量精力构建复杂 Harness 的团队，可能在未来几年内发现自己的工作被模型的进步所"吞噬"。

### 3. 实证研究的质疑

METR 和 Scale AI 的 SWE-Atlas 研究显示，**不同 Harness 对模型性能的影响处于误差范围内**，差异微小。

这个数据对 Big Harness 阵营是一个不小的打击。如果精心优化的 Harness 只能带来统计误差级别的提升，那么投入大量工程资源去构建复杂架构是否值得？

### 4. OpenAI 的"双面"立场

有趣的是，OpenAI 在这个问题上表现出一种"双面"立场：

- 一方面，他们指出 Harness Engineering 入门简单，暗示这不是一个高门槛的领域
- 另一方面，他们又投资了全球最成功的开源 Harness 项目 **OpenClaw**

这种看似矛盾的态度，或许反映了 OpenAI 对 Harness 价值的真实判断：它可能不是核心竞争力的来源，但确实是生态系统中不可或缺的一环。

## 二、Big Harness 阵营：编排层的价值重估

### 1. 生产级智能体的共同架构

Big Harness 阵营的一个重要论据是：观察当前所有生产级智能体（Claude Code、Cursor 的智能体、Manus 等），它们都遵循**统一的核心循环架构**。

这个发现暗示，可能并不存在无数种 equally valid 的架构选择，而是有一个相对最优的解空间。在这个解空间里，Harness 的设计质量直接决定了产品的上限。

### 2. Jerry Liu 的"Harness 即价值"论

Jerry Liu（LlamaIndex CEO）提出了一个鲜明的观点：**模型 Harness 是挖掘 AI 价值的关键**。

他认为，当前最大的障碍不是模型能力的不足，而是对模型的**上下文和工作流工程能力**。这一点在通用工具中尤为突出——同样的底层模型，在不同的 Harness 下可能表现出截然不同的效果。

### 3. Pi 的实证：Harness 优化的惊人效果

Big Harness 阵营有一个强有力的实证：**Pi**（一个 Harness 优化项目）在一个下午的时间内，仅通过优化 Harness，就让 **15 个大模型的编码能力**得到了**大幅提升**。

这个案例表明，Harness 的优化空间可能远比 Big Model 阵营认为的要大。如果正确的 Harness 设计能让普通模型达到接近顶级模型的效果，那么 Harness Engineering 的价值就不容忽视。

### 4. 商业模式的验证

Big Harness 阵营还有一个间接但有力的论据：**市场估值**。

Cursor 的估值已经达到 **500 亿美元**，而它本质上就是一个高级 Harness（在 VS Code 基础上叠加 AI 能力）。这个估值水平表明，资本市场对 Harness 的价值给予了高度认可。

相比之下，单纯售卖模型的商业模式（如早期 OpenAI 的 API 模式）的估值倍数，往往低于拥有强 Harness 产品的公司。

## 三、Latent.Space 的中间立场：务实主义的胜利

面对两个阵营的激烈争论，Latent.Space 采取了一种更为务实的中立立场。

### 1. 承认"苦涩教训"，但看到 Harness 的现实价值

Latent.Space 承认 AI 领域历史上确实存在一个"苦涩教训"（Bitter Lesson）：长期来看，通用方法（如深度学习、大规模训练）往往优于人工设计的特定领域知识。

按照这个逻辑，Big Model 阵营似乎更有道理——如果模型足够强大，它应该能够自动学习到最优的工作方式，而不需要人工设计的 Harness。

但 Latent.Space 也指出，**现实往往比理论更复杂**。在当前的实际应用场景中，Harness Engineering 确实带来了可测量的、有时甚至是巨大的价值提升。

### 2. Agent Labs 的兴起作为佐证

Latent.Space 特别提到了 **Agent Labs** 的兴起作为 Harness Engineering 价值的佐证。

Agent Labs 是一类专注于构建 AI Agent 基础设施的创业公司，它们的核心产品往往就是各种形式的 Harness（编排框架、Agent 框架、工作流引擎等）。

这个领域的快速发展和大量融资，表明资本市场和创业生态都认为 Harness Engineering 是一个有真实需求的赛道。

### 3. AIE Europe 的行业认可

最有力的佐证可能来自 **AIE Europe**（AI Engineering Europe）开设的**全球首个 Harness Engineering 赛道**。

作为一个权威的行业会议和社群，AIE Europe 决定开设专门的 Harness Engineering 赛道，意味着这个领域已经获得了足够的行业认可，值得作为一个独立的技术方向来深入探讨。

这比任何理论争论都更有说服力——当行业共识认为一个领域值得专门开设会议赛道时，这个领域的价值就已经得到了市场的验证。

## 四、在争论中寻找第三条路

读完整篇文章，我最大的感受是：**这场争论本身就是一个伪命题**。

### 1. 二元对立的陷阱

Big Model 和 Big Harness 的二元对立，很大程度上是**商业利益驱动的叙事建构**，而非技术本质的真实反映。

卖模型的公司自然会强调模型的核心地位，卖 Harness 的公司自然会强调编排层的价值。这种立场先行的话语体系，往往会遮蔽技术决策的复杂性。

现实中的优秀 AI 产品，往往是**模型能力和 Harness 设计的精妙结合**。强行把它们割裂开来，然后争论哪个更重要，就像争论汽车的发动机和变速箱哪个更重要一样——脱离了具体场景，这个问题本身就没有意义。

### 2. 第三条路：场景化的价值判断

我认为真正有价值的问题不是"Harness Engineering 有没有价值"，而是**"在什么场景下，投入多少资源去优化 Harness，能够获得最大的 ROI"**。

这个问题的答案显然是**场景依赖**的：

- 对于**通用型 AI 助手**，模型能力的提升可能带来更直接的用户体验改善，Harness 的优化空间相对有限。
- 对于**特定领域的专业工具**（如代码编辑器、数据分析平台），Harness 的设计质量往往直接决定了产品的可用性和效率。
- 对于**需要复杂多步骤推理的任务**，Harness 的编排能力可能比单个模型的能力更重要。

聪明的团队不会盲目站队，而是会**根据具体场景，动态调整模型投入和 Harness 投入的比例**。

### 3. 长期视角：当模型能力持续提升

我们还必须考虑一个长期趋势：**模型能力在持续提升**。

如果按照这个趋势推演，Big Model 阵营的预言可能是正确的——随着模型能力的增强，现在需要复杂 Harness 才能实现的功能，未来可能通过更简洁的架构就能完成。

但这并不意味着 Harness Engineering 现在没有价值。技术演进是渐进的，在通往"终极模型"的路上，我们仍然需要高质量的 Harness 来最大化当前模型的能力。

更何况，**即使模型能力持续增强，Harness 的需求也不会消失，只是形态会演变**。从复杂的编排框架，到更简洁的封装层，Harness 会一直存在，只是复杂度会随着模型能力的提升而降低。

### 4. 给从业者的建议

对于正在这个领域工作的从业者，我的建议是：

**不要被商业叙事绑架**。选择技术路线时，应该基于具体场景的需求，而不是盲从某个阵营的教条。

**保持动态视角**。模型能力和 Harness 设计的最优组合是动态变化的，今天需要复杂 Harness 的场景，明天可能只需要简单的封装。

**投资于可迁移的能力**。无论是深入模型优化，还是精通 Harness 设计，都应该选择那些在未来技术演进中仍然有价值的能力。

**关注真实的用户价值**。最终，技术的价值不在于它有多先进，而在于它能为用户解决什么问题。模型能力再强，Harness 设计再精妙，如果不能转化为用户价值，就只是自嗨。

## 结语：在争论之外，寻找真实的问题

回到文章开头的问题：Harness Engineering 到底有没有真实价值？

我的答案是：**这个问题本身就是误导性的**。

真正值得问的不是 Harness 是否有价值，而是在具体场景下，如何最优地组合模型能力和 Harness 设计，以创造最大的用户价值。

Big Model 和 Big Harness 的争论，本质上是两个商业阵营的话语权之争。作为从业者，我们应该跳出这个二元对立的框架，在具体的场景中寻找最优解。

技术的发展从来不是线性的，也不会被某个单一的范式所主导。在 AI 工程的下一个十年，我们可能会看到模型能力和 Harness 设计的深度融合，也可能会看到全新的架构范式取代当前的争论。

无论如何，保持开放的心态，关注真实的问题，而不是被商业叙事所裹挟，这可能是我们在快速变化的技术浪潮中，能够保持清醒和判断力的关键。
