### 1. Gemini 3.1 Pro 发布

**🏷️ 中文标题**：Gemini 3.1 Pro 发布——Google 新一代旗舰模型，价格仅为 Claude Opus 的一半

**📌 核心观点**：Google 发布 Gemini 3.1 系列首个版本，性能接近 Claude Opus 4.6，但价格只有其一半。

**💡 为什么值得关注**：
这是 Google 在大模型领域的重要更新，标志着价格战的进一步升级。对于开发者来说，这意味着可以用更低的成本获得顶级性能的模型。

**📋 关键要点**：
- **价格体系**：与 Gemini 3 Pro 相同，200K token 以下为 $2/百万输入、$12/百万输出；200K-1M token 为 $4/百万输入、$18/百万输出
- **性能对比**：基准测试成绩与 Claude Opus 4.6 非常接近，但价格不到后者的一半
- **特色功能**：重点宣传了相比 Gemini 3 Pro 改进的 SVG 动画性能
- **实测体验**：Simon 测试了"生成鹈鹕骑自行车的 SVG"，模型思考了 323.9 秒后生成了不错的结果，包括鹈鹕双腿、篮子里的鱼等细节
- **目前问题**：发布首日模型响应非常慢，简单的"hi"需要 104 秒，部分测试遇到"高需求"或"超时"错误
- **模型标识**：已添加到 llm-gemini 插件：gemini-3.1-pro-preview 和 gemini-3.1-pro-preview-customtools
- **与 Deep Think 的关系**：上周发布的 Gemini 3 Deep Think 是我们首次接触 3.1 系列

**⭐ 推荐**：值得精读

**🔗 原文链接**：https://simonwillison.net/2026/Feb/19/gemini-31-pro/

### 2. SWE-bench 2026年2月排行榜更新

**🏷️ 中文标题**：SWE-bench 2026年2月排行榜发布——Claude Opus 4.5 小幅领先 4.6，中国模型表现亮眼

**📌 核心观点**：非实验室自报的 SWE-bench 基准测试更新，Claude Opus 4.5 意外领先 4.6，多款中国模型进入前十。

**💡 为什么值得关注**：
这是少有的非实验室自报的基准测试结果，更具参考价值。中国模型在编程基准测试中的表现值得关注。

**📋 关键要点**：
- **测试背景**：SWE-bench 是实验室喜欢在模型发布时引用的基准测试之一，官方排行榜更新不频繁，但这次对当前一代模型进行了完整运行
- **测试设置**：使用"Bash Only"基准测试，运行 mini-swe-bench agent（约9000行Python）对抗 SWE-bench 数据集
- **数据集规模**：2294个真实世界例子，来自12个开源仓库：django/django(850)、sympy/sympy(386)、scikit-learn(229)等
- **重要修正**：Bash only 基准测试运行的是 SWE-bench Verified，不是原始 SWE-bench。Verified 是人工精选的500个样本子集
- **前十排名亮点**：
  - Claude Opus 4.5 击败 Opus 4.6（仅领先约1个百分点）
  - 第二名：Gemini 3 Flash
  - 第三名：MiniMax M2.5（中国实验室 MiniMax 上周发布的 229B 模型）
  - 其他中国模型：GLM-5、Kimi K2.5、DeepSeek V3.2 也进入前十
- **OpenAI 表现**：GPT-5.2 排名第6，但值得注意的是他们最好的编程模型 GPT-5.3-Codex 未参与（可能因为尚未在 API 中可用）
- **测试限制**：该基准测试对每个模型使用相同的系统提示，这对公平比较很重要，但也意味着不同 harness 或优化提示的质量未被测量

**⭐ 推荐**：值得精读

**🔗 原文链接**：https://simonwillison.net/2026/Feb/19/swe-bench/

### 3. AI 颠覆已至

**🏷️ 中文标题**：《我们等待已久的 AI 颠覆已至》——Paul Ford 纽约时报深度观点文章

**📌 核心观点**：2025年11月是一个转折点，AI 编程工具从"有用但笨拙"变成了"能连续运行一小时创建完整网站和应用"。

**💡 为什么值得关注**：
Paul Ford 作为前咨询公司 CEO，对软件成本和商业影响有独特的视角。这篇文章充满了值得引用的金句。

**📋 关键要点**：
- **转折点描述**：Paul 描述了许多程序员都观察到的"11月时刻"
- **个人体验**：
  - Claude Code 以前是一个有用的编程助手，但在11月突然变得好多了
  - 从那以后，Simon 一直在完成那些在文件夹里搁置了十年或更久的副业项目
  - 每天大约花半小时自己的时间，加上一小时 Claude 的时间
- **能力跃升**：
  - 之前：AI 编程工具通常有用，但断断续续、笨拙
  - 现在：机器人可以连续运行一整小时，创建完整的、设计好的网站和应用，可能有缺陷，但可信
- **商业影响**（作为前咨询公司 CEO 的视角）：
  - 当你看到一个大语言模型轻松解决一些可怕的、昂贵的问题时，你会感觉到地球在移动
  - 例子1：重启自己混乱的个人网站——换以前会花25,000美元请别人做
  - 例子2：朋友请他转换一个大的、棘手的数据集——下载、清理、美化、让它易于探索，换以前会收350,000美元
- **成本对比**：
  - 以前：定制软件贵得惊人
  - 现在：当星星对齐、提示词工作时，可以在周末和晚上做数十万美元的工作（对 Simon 来说是有趣的），只需 Claude 200美元/月的计划

**⭐ 推荐**：值得精读

### 4. Martin Fowler 谈 LLM 与专家通才

**🏷️ 中文标题**：Martin Fowler：LLM 正在吞噬专业技能——专家通才的角色将更受重视？

**📌 核心观点**：LLM 正在减少对专业前端和后端开发者的需求，LLM 驱动技能比平台使用细节更重要。

**💡 为什么值得关注**：
Martin Fowler 是软件开发领域的思想领袖，他的观点值得认真思考。这涉及到未来软件开发团队的组织方式。

**📋 关键要点**：
- **核心论断**：LLMs are eating specialty skills（LLM 正在吞噬专业技能）
- **具体影响**：
  - 对专业前端和后端开发者的需求将减少
  - LLM 驱动技能变得比平台使用细节更重要
- **两个开放性问题**：
  - 这会导致专家通才（Expert Generalists）的角色更受重视吗？
  - 还是说 LLM 编写大量代码的能力意味着它们会绕过竖井而不是消除它们？

### 5. 博客赞助模式实验

**🏷️ 中文标题**：Simon Willison 首次尝试博客和 Newsletter 赞助模式

**📌 核心观点**：长期抵制赞助的 Simon 终于决定尝试 Troy Hunt 的极简赞助模式，以平衡独立性和运营成本。

**💡 为什么值得关注**：
这是技术博主变现的一个重要案例。Simon 一直非常重视自己的独立声音，这次选择的赞助模式值得其他独立博主参考。

**📋 关键要点**：
- **历史态度**：长期以来一直抵制接受赞助，非常珍视自己作为独立声音的可信度
- **转变契机**：了解到 Troy Hunt 的赞助方式——简单的文字横幅，无 JavaScript、无 Cookie、不显眼但能为赞助商提供价值
- **模式特点**：按周出售赞助，赞助商获得博客顶部的不显眼横幅和 Newsletter 顶部的赞助信息
- **核心原则**：不会为了赞助而写内容，相信赞助商会理解，独立声音的可信度是拥有受众的关键原因

**⭐ 推荐**：建议浏览

### 6. 25年后终于接受强类型

**🏷️ 中文标题**：25年编程生涯后，Simon Willison 终于开始接受类型提示甚至强类型

**📌 核心观点**：AI 编程助手改变了类型系统的成本收益比——以前需要人工打字的负担，现在由 AI 承担。

**💡 为什么值得关注**：
这是一个非常个人化但具有普遍意义的观察。AI 不仅改变了我们写代码的方式，也改变了我们对编程语言特性的态度。

**📋 关键要点**：
- **历史态度**：25年以上的编程生涯中，一直抵制类型提示或强类型
- **抵制原因**：类型系统会减慢代码迭代速度，特别是在对生产力至关重要的 REPL 环境中
- **态度转变**：如果由编程代理来完成所有打字工作，明确定义所有类型的好处突然变得更有吸引力

**⭐ 推荐**：建议浏览

## 💭 彪彪思语

今天的早报里，Paul Ford的那段话特别让我有共鸣："2025年11月是一个转折点，AI编程工具从'有用但笨拙'变成了'能连续运行一小时创建完整网站和应用'"。

我想起最近自己也有类似的体验——之前Claude Code虽然有用，但总觉得断断续续的；但最近，它真的能连续运行很长时间，完成一些以前想都不敢想的任务。

这个转变，可能比很多模型发布都更重要。因为模型再聪明，如果用起来太笨拙，也很难产生实际价值。但当工具真的"能用"了——甚至能"连续用一小时"——那整个游戏规则就变了。

Paul Ford作为前咨询公司CEO，他算的那笔账特别有意思：以前要花25,000美元请人做的网站，现在自己周末就能搞定；以前要收350,000美元的咨询项目，现在用Claude 200美元/月的计划就能完成。

这种成本结构的变化，可能比任何技术突破都更有颠覆性。

Martin Fowler提出的那个问题也值得思考：LLM正在吞噬专业技能，那专家通才（Expert Generalists）的角色会不会更受重视？

我觉得可能会。因为当LLM能帮你搞定很多专业细节时，真正值钱的就变成了：知道该做什么、知道如何把事情组合起来、知道如何判断好坏——这些能力，恰恰是专家通才的核心价值。

这让我想起之前写的那篇Agent工程时代的文章——我们这些工程师的价值，可能不在于掌握某个特定框架的细节，而在于系统设计能力、品味判断力、工程化思维。

这些东西，LLM替代不了。
