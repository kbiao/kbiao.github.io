1. Ladybird adopts Rust, with help from AI

🏷️ 中文标题：Ladybird浏览器采用Rust，AI辅助迁移——两周完成25,000行代码，零回归验证

📌 核心观点：AI辅助大规模代码迁移，两周完成人工数月工作量，保持零回归。

💡 为什么值得关注：
这是一个高级AI编码代理在关键代码项目中的成功案例，展示了如何在保持零回归的前提下进行大规模代码迁移。对于任何考虑技术栈迁移的团队来说，这都是一个值得学习的范本。

📋 关键要点：

  • 项目背景：Ladybird浏览器团队在等待Swift生态成熟几年后，决定转向Rust作为内存安全语言
  • 迁移目标：从LibJS（JavaScript引擎）开始，包括词法分析器、解析器、AST和字节码生成器
  • AI工具：使用Claude Code和Codex进行翻译，采用人工指导而非自主代码生成
  • 实施方式：数百个小提示词，由人类决定迁移顺序和Rust代码的最终形态
  • 验证标准：两个管道必须产生字节级完全相同的输出
  • 成果数据：约25,000行Rust代码，整个迁移耗时约两周（人工需数月）
  • 质量保证：验证Rust解析器生成的每个AST与C++版本完全相同，零回归
  • 关键因素：test262测试套件的存在是这种规模项目的巨大突破口

⭐ 推荐：值得精读

🔗 原文链接：https://simonwillison.net/2026/Feb/23/ladybird-adopts-rust/

2. Writing about Agentic Engineering Patterns

🏷️ 中文标题：开始编写Agentic工程模式——Simon Willison启动AI时代软件工程系统化指南项目

📌 核心观点：系统化整理AI辅助编程的最佳实践和模式，受《设计模式》启发，以章节形式呈现。

💡 为什么值得关注：
Simon Willison正在创建一个系统化的Agentic工程模式指南，这将成为AI时代软件工程的重要参考资料。这标志着AI编程从”经验主义”走向”体系化”的重要一步。

📋 关键要点：

  • 项目目标：收集和记录Agentic Engineering Patterns——帮助在新的编码代理开发时代获得最佳结果的编码实践和模式
  • 定义澄清：
    • Agentic Engineering：专业软件工程师使用编码代理来改进和加速工作，放大现有专业知识
    • Vibe Coding：完全不关注代码的编码方式，常与非程序员使用LLM编写代码相关联
  • 内容形式：受《设计模式》启发，以章节形式的模式呈现
  • 已发布章节：
    1. Writing code is cheap now：讨论Agentic工程的核心挑战——生成初始可用代码的成本几乎降至零
    2. Red/green TDD：描述测试优先开发如何帮助代理编写更简洁可靠的代码
  • 更新计划：每周1-2章的速度添加更多内容
  • 内容质量保证：所有文字由Simon本人撰写，不发布AI生成的写作
  • 格式创新：使用”指南（guide）”格式——章节集合，每个章节本质上是博客文章，但日期不那么突出，设计为随时间更新而非冻结

⭐ 推荐：值得精读

🔗 原文链接：https://simonwillison.net/2026/Feb/23/agentic-engineering-patterns/

3. The Claude C Compiler: What It Reveals About the Future of Software

🏷️ 中文标题：Claude C编译器：揭示软件的未来——Chris Lattner深度分析AI时代软件工程的新边界

📌 核心观点：AI编译器项目展示了当前AI能力边界和未来方向，Chris Lattner提供了权威视角。

💡 为什么值得关注：
Chris Lattner（Swift、LLVM、Clang、Mojo之父）对Claude C编译器的深度分析，提供了权威视角。作为编译器领域的顶级专家，他的看法值得认真思考。

📋 关键要点：

  • 项目背景：2月5日Anthropic的Nicholas Carlini发表了使用并行Claude构建C编译器的项目
  • Chris Lattner的评价：
    • 总体印象深刻：CCC看起来不像是实验性研究编译器，而更像是合格的教科书实现
    • 相当于优秀本科生团队在项目早期可能构建的系统
  • AI时代的软件工程洞见：
    • 好的软件依赖于判断、沟通和清晰的抽象，AI放大了这一点
    • AI编码是实现的自动化，因此设计和管理变得更加重要
    • 手动重写和翻译工作正在成为AI原生任务，自动化了一大类工程工作
  • 局限性分析：
    • 几个设计选择表明优化方向是通过测试，而不是像人类那样构建通用抽象
    • 这些缺陷是有信息价值的，而非令人惊讶
    • 当前AI系统擅长组装已知技术和针对可衡量的成功标准进行优化
    • 但在生产质量系统所需的开放式泛化方面存在困难
  • 深层开放性问题：
    • 如果在数十年公开可用代码上训练的AI系统能够重现熟悉的结构、模式甚至具体实现
    • 那么学习和复制之间的界限究竟在哪里？

⭐ 推荐：值得精读

🔗 原文链接：https://simonwillison.net/2026/Feb/22/ccc/

💭

今天的三篇文章连在一起看，正好勾勒出AI时代软件工程的新图景。

最让我思考的是Simon Willison那句话——“Writing code is cheap now”（现在写代码很便宜了）。这句话背后的意味很深：当生成代码的成本几乎降至零时，什么才是真正有价值的？

Ladybird的Rust迁移案例给了我一个很好的答案。他们用AI辅助完成了25,000行代码的迁移，两周完成人工数月的工作量，但关键在于——test262测试套件的存在是这种规模项目的巨大突破口。

没有测试，AI生成的代码可能很便宜，但也可能很危险。有了测试，AI才能真正发挥威力。这让我想起Mitchell Hashimoto的Harness工程思想——“Anytime you find an agent makes a mistake, you take the time to engineer a solution such that the agent never makes that mistake again”。

Chris Lattner的分析也很有意思。他说Claude C编译器”看起来不像是实验性研究编译器，而更像是合格的教科书实现”，但同时也指出——“几个设计选择表明优化方向是通过测试，而不是像人类那样构建通用抽象”。

这个观察很深刻。当前AI系统擅长组装已知技术和针对可衡量的成功标准进行优化，但在生产质量系统所需的开放式泛化方面存在困难。

Simon Willison启动的Agentic工程模式项目，我觉得正是在回应这个挑战。受《设计模式》启发，他要系统化整理AI辅助编程的最佳实践和模式。这标志着AI编程从”经验主义”走向”体系化”的重要一步。

那么，回到那个问题——当写代码很便宜时，什么才是真正有价值的？

我想答案可能是：

  1. 判断和品味——知道该做什么，知道什么是好的
  2. 测试和验证——确保AI生成的代码是可靠的
  3. 设计和架构——构建通用抽象，而不只是通过测试
  4. 模式和原则——把经验系统化，让AI第一次就做对

这些东西，LLM替代不了。
