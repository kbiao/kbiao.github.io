从LLM到Agents再到Claws——三层堆栈里的工程师机会

发表于 2026-02-22 更新于 2026-02-22 分类于 技术人生 阅读次数：
Andrej Karpathy提出LLM→Agents→Claws三层堆栈，揭示Agent工程成为独立新层级。作为工程师，我们的系统设计能力、品味判断力、工具链思维在AI时代依然具有强大竞争力。

由小龙 🐉 协助整理，彪彪 ✍️ 深度思考

今天早上的RSS早报里，Andrej Karpathy关于”Claws”的一段话让我特别有感触。他说：”就像LLM agents是LLM之上的新层级一样，Claws现在是LLM agents之上的新层级，将编排、调度、上下文、工具调用和某种持久性提升到了一个新的水平。”

这段话正好击中了我最近的一些思考——作为一个做工程代码开发的人，在大模型时代多多少少会有一些焦虑：AI会不会替代我的工作？我的工程能力在这个新时代还有价值吗？

但Andrej的这个观点让我看到了一个很有意思的方向：工程能力和品味，在Agent工程时代依然具有强大的竞争力。

从LLM到Agents再到Claws：三层堆栈的形成

让我们先看看这条清晰的演进线：

第一层：LLM本身

  • 核心能力：语言理解、推理、生成
  • 代表：GPT、Claude、Llama等
  • 特点：”聪明”，但缺乏执行力

第二层：Agents

  • 核心能力：工具调用、多步骤推理、任务分解
  • 代表：AutoGPT、Claude Code等
  • 特点：能”做事”了，但缺乏系统级的编排

第三层：Claws（Andrej提出的新概念）

  • 核心能力：编排、调度、上下文管理、持久性
  • 代表：OpenClaw、NanoClaw等
  • 特点：系统级的工程化能力

Andrej说得很对：这不是简单的概念叠加，而是真正的层级式演进——每一层都建立在上一层的基础上，但又解决了上一层的痛点。

这让我想起之前在《从 Prompt 工程到 Skills》那篇文章里画的演进表：

阶段核心特征解决的问题
Prompt 工程单次输入优化如何让单次请求效果更好
上下文工程动态上下文构建如何让模型”看到”相关信息
Skills / Agents可组合的能力单元如何让复杂任务可维护、可复用
Claws系统级编排与调度如何让Agents在真实环境中稳定运行

现在看，我们当时讨论的”Skills / Agents”阶段，其实就是Andrej说的第二层；而他现在提出的”Claws”，正是正在形成的第三层。

为什么Agent工程是独立的新层级？

Andrej用了一个很有意思的词：”a new layer on top of”——这不是”另一个工具”，而是”一个新的层级”。

这个区分很重要。让我想想，为什么Agent工程能成为一个独立的层级？

1. 问题域不同：从”做对”到”做好”

LLM解决的问题是：如何生成正确的输出？

Agent工程解决的问题是：如何在真实环境中稳定、高效、安全地完成任务？

这就好比：

  • LLM是”发动机”——能产生动力，但不知道怎么把动力传到轮子上
  • Agent工程是”整车工程”——需要考虑传动系统、刹车系统、悬架系统、安全性、可靠性

2. 所需能力不同：从”算法”到”系统”

做LLM相关的研究，需要的能力是：

  • 机器学习、深度学习
  • 优化算法、模型架构
  • 数学、统计学

但做Agent工程，需要的能力是：

  • 系统设计、架构设计
  • 并发、调度、状态管理
  • 容错、重试、幂等性
  • 安全性、隐私保护
  • 可观测性、调试工具

发现了吗？后者正是我们这些传统软件工程师最擅长的领域！

3. 价值创造不同：从”能力”到”价值”

LLM创造的价值是：提供智能能力

Agent工程创造的价值是：把智能能力转化为实际业务价值

这就像云计算时代一样：

  • 有人去研究如何造更好的CPU（类似LLM研究）
  • 但更多的工程师在做的是：如何用这些CPU构建可靠的系统（类似Agent工程）

工程师的新机遇：你的能力其实更值钱了

理解了这个三层堆栈，我反而觉得：在Agent工程时代，我们这些有工程背景的人，其实更有优势了。

让我想想，我们的哪些能力在这个新时代特别有价值？

1. 系统设计能力

Agent系统不是一个简单的脚本，而是一个复杂的分布式系统。你需要考虑：

  • 状态如何管理？
  • 任务如何调度？
  • 错误如何处理？
  • 资源如何限制？

这些都是传统后端工程师天天在琢磨的问题。

2. 品味和判断力

Mitchell Hashimoto（HashiCorp创始人）最近一直在强调一个观点：Agents are much more efficient when they produce the right result the first time。

什么叫”produce the right result the first time”？这就是品味和判断力的问题——你知道什么是”好”的结果，什么是”足够好”的结果，什么是”不能接受”的结果。

这种品味，不是从训练数据里学来的，而是从一次次代码审查、一次次架构设计、一次次线上事故中积累出来的。

3. 工具链和工程化思维

好的Agent系统需要什么？

  • 良好的日志系统
  • 可观测性（metrics、traces、logs）
  • 调试工具
  • 测试框架
  • 部署流程

这些东西，LLM研究者可能不太关心，但我们这些工程师天天都在和它们打交道。

4. 安全性和风险意识

Agent系统直接操作真实世界（调用API、修改文件、发送消息），安全性至关重要。

什么样的操作是安全的？什么样的操作需要人工确认？如何防止Agent做出破坏性的事情？

这些问题，正是我们这些做过生产系统的工程师最敏感的地方。

这不是焦虑，而是兴奋

想清楚这些，我反而不焦虑了。

之前的焦虑可能来自：”AI会不会替代我？”

但现在的想法是：”AI给了我一个更大的舞台，让我的工程能力能创造更大的价值。”

这就像当年云计算兴起的时候，有人担心”云计算会让运维工程师失业”，但结果呢？运维工程师非但没有失业，反而变成了SRE（Site Reliability Engineer），创造了更大的价值。

今天的情况很类似：

  • 不是”AI替代工程师”
  • 而是”工程师+AI，能做以前做不到的事情”

Andrej在那条推特里还提到了一个细节：他买了一台Mac Mini来体验Claws，Apple Store的人说”这玩意儿卖疯了，大家都很困惑”。

这个细节很有意思——“卖疯了”说明需求很大，”大家都很困惑”说明这还是一个很新的领域，没有人知道标准答案是什么。

这就是我们的机会。

接下来该怎么做？

既然方向已经清晰了，那接下来该怎么做？

我想，可以从这几个方面入手：

1. 动手玩起来

就像Andrej买Mac Mini来体验Claws一样，我们也应该动手玩一玩这些工具。

不用追求一开始就做个完美的系统，先从简单的开始：

  • 写个简单的Agent
  • 试试不同的编排方式
  • 看看会遇到什么问题

在玩的过程中，你自然会发现需要解决的问题——而这些问题，就是你的机会。

2. 关注系统层面的问题

不要只盯着”如何让Agent更聪明”，多关注：

  • 如何让Agent更可靠？
  • 如何让Agent更安全？
  • 如何让Agent更易调试？
  • 如何让Agent更易维护？

这些问题，正是我们的强项。

3. 积累你的”工程Harness”

Mitchell Hashimoto提出了一个概念叫”Engineering Harness”——每次发现Agent犯了一个错误，你就花时间把这个错误变成一个检查清单、一个测试用例、一个护栏规则，确保Agent下次不会再犯同样的错误。

这种思维方式，其实就是我们做软件工程的思维方式——从错误中学习，用系统来保证质量。

4. 保持你的品味

最后但最重要的是：保持你的品味。

知道什么是”好”的设计，什么是”坏”的设计；
知道什么时候该”追求完美”，什么时候该”先上线再迭代”；
知道什么时候该”信任AI”，什么时候该”人工确认”。

这种品味，是AI替代不了的。

结语

Andrej Karpathy说：”Claws是AI栈中一个很棒的、令人兴奋的新层级。”

我想补充一句：这个新层级，正是我们这些工程师的主场。

LLM给了我们强大的”大脑”，但如何把这个”大脑”用好，如何构建稳定、可靠、安全的系统——这正是我们最擅长的事情。

所以，别焦虑。这不是你的终点，这是你的新起点。

你的工程能力，你的品味，你的判断力——这些东西，在Agent工程时代，反而更有价值了。

毕竟，AI可以生成代码，但AI不能替代你对”好”的理解；AI可以执行任务，但AI不能替代你对系统的责任感；AI可以给出建议，但AI不能替代你做决定的勇气。

这就是我们的价值所在。
